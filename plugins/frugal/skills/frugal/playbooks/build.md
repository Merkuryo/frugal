# Build: make something new

1. **Goal and smallest version.** One line each. If the request is ambiguous on something only the human can decide (taste, audience, scope), ask once, with options.
2. **Shape first.** Name the data shape, structure or outline before writing the thing itself.
3. **Find what exists.** `scout` searches for existing code, templates or prior work to reuse. Reuse beats writing.
4. **Plan in verifiable units.** 2–6 steps, each ending in something you can check. Skip the plan for a single unit.
5. **Do.** You or `worker`, one unit at a time. Check each unit before the next.
6. **Hard design call?** If two reasonable designs remain and the choice is costly to undo, go to `decide.md` (L2) before building further.
7. **Verify on the real artifact.** Run it, open it, render it. For code: tests that exercise behavior, not implementation.
8. **Report.** What exists now, how it was checked, what is left.
